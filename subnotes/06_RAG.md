# RAG (Retrieval-Augmented Generation)
- 외부의 데이터 저장소에서 문서를 검색하고, 검색 결과를 기반으로 LLM이 답변을 생성하도록 하는 아키텍처이다.
- RAG는 Non-Parametric Knowledge를 질문 시점에 검색해 모델과 함께 사용한다.  
    - cf. Parametric Knowledge : LLM이 학습 과정에서 가중치 안에 압축시켜둔 지식
- LLM은 학습 시점까지의 데이터만 알고 있고 학습 이후에 생긴 정보나 비공개 데이터는 알 수 없기 때문에 RAG는 질문 시점에 필요한 문서를 검색해 프롬프트에 넣어줌으로써 이러한 한계를 보완한다.

## RAG에서 발생하는 문제
### 1. 관련없는 문서가 검색되는 문제
#### 해결 방법
문서를 나누는 크기 조정, 임보뎅 모델 교체, 하이브리드 검색, Reranking 등을 적용

### 2. Hallucination
#### 해결 방법
프롬프트 강화.  
검색 결과 점수가 너무 낮으면 답변을 만들지 않거나 정보를 찾을 수 없다고 반환하도록 설계.

### 3. 비슷한 내용의 반복
#### 해결 방법
- 검색 결과를 분산해서 뽑는다.  
- 인덱싱 전에 중복 문서를 정리하거나 저장 단계에서 비슷한 조각 제거. 

### 4. 긴 문서에서 앞뒤 맥락이 끊김
#### 해결 방법
- 문서를 나눌 때 앞뒤 내용을 겹치도록 한다.  
- 문서 구조를 잘 반영하여 나눈다.  
- Parent-child chunking : 더 큰 원문 맥락을 함께 가져온다.

## RAG 파이프라인 구성
## Indexing
문서롤 로딩, 전처리, 청킹, 임베딩하여 벡터 DB에 저장하기까지의 전체 과정이다.
### 1. Document Loading (Parsing)
다양한 형식의 문서를 텍스트로 추출하여 RAG 파이프라인에 투입할 수 있는 형태로 변환하는 과정이다. 문서 형식별로 다른 파싱 로직이 필요하다.  
반환 구조 : 텍스트와 메타데이터

#### 형식별로 다른 파서
- PDF Parsing
    - 주요 파싱 라이브러리 : PyPDF2, pdfplumber, PyMuPDF, Tesseract
    - 구조 분석 기반 PDF 파서 : Docling, LlamaParse, Unstructured
### 2. Text Preprocessing
문서에서 추출된 텍스트를 ***청킹 전***에 노이즈를 제거하고 정리하는 과정이다.  
전처리는 노이즈 제거와 정보 보존 사이의 균형을 맞추는 것이 중요하다.
#### 주요 전처리 작업
- 불필요한 문자 제거
- 공백 정규화
- 빈 줄 정리
- 헤더/푸터 제거
- HTML 태그 제거
- 유니코드 정규화

### 3. Chunking
문서를 검색과 임베딩에 적합한 크기의 텍스트 조각으로 분할하는 과정이다.  
만약 긴 문서를 그대로 하나의 벡터로 만들면 두 가지 문제가 발생한다.
1. 임베딩 모델 입력 제한 : 임베딩 모델에는 토큰의 최대 입력 길이가 제한되어 있다. 만약 이를 초과하면 텍스트가 잘린다.
2. 유사도 희석 : 문서 전체의 의미가 평균화되어 유사도가 희석되고 검색 정확도가 떨어진다. 

#### 주요 청킹 전략
- Fixed-size Chunking : 글자나 토큰 수로 분할
    - 장점: 어떤 문서에나 적용할 수 있다.
    - 단점: 문장이 잘려서 문맥이 끊길 수 있다.
- Regex & Delimiter Chunking : 구분자로 분할
    - 계층적 구분자 전략
- Semantic Chunking : 문장 간 임베딩 유사도를 계산하여, 의미 단위로 분할
    - 단점: 비용이 높다
- Parent-Child Chunking : 부모와 자식 계층으로 분할

문서 특성에 따라 청킹 전략을 다르게 선택하는 것이 좋다.

### 4. Embedding
#### 1) Tokenization (+ 정수 Encoding)
- 텍스트를 모델이 처리할 수 있는 토큰 단위로 분리하고 정수 ID로 변환하는 과정을 의미한다.  
- **모델과 토크나이저를 반드시 맞춰서 사용해야 한다.**  e.g., 
    - GPT계열(생성형) 모델은 GPT 계열 토크나이저 : 이전 토큰들을 바탕으로 다음 토큰 예측하는 구조  
    - BERT계열 모델은 BERT 계열 토크나이저 : 문장을 이해하고 분류하는 작업에 맞춰진 구조. 특수 토큰을 적극적으로 사용한다.
- `tokenizer.encode()` 는 `tokenize()`와 정수 인코딩을 한 번에 수행한다.  
cf.`decode()`는 정수 ID 시퀀스를 다시 원본 텍스트로 복원한다.

##### 주요 방식
- word : 단어 단위
- subword : 빈도 기반 부분 문자열, 학습 데이터에 없던 단어를 처리할 수 있다.
- character : 글자 단위

#### 2) Text Embedding
정수 ID를 의미가 반영된 벡터로 변환한다. 비슷한 의미의 텍스트끼리는 벡터 공간에서 가까운 위치에 배치하고, 다른 의미의 텍스트는 먼 위치에 배치한다.  

##### 핵심 특성
- 고정 길이 : 벡터를 저장하고 유사도를 검색하려면 모든 벡터의 차원이 같아야 한다.
- 의미 보존 : 비슷한 의미는 가까운 위치에, 다른 의미는 먼 위치에.
- 수치 연산 가능 : 수학 연산으로 텍스트 간 유사도 측정 가능
- 모델 의존적 : 임베딩에 사용한 모델에 따라 결과가 달라진다. 인덱싱과 검색에서 반드시 같은 모델을 사용한다.

`model.encode(sentences)` : Tokenization &rarr; 정수 인코딩 &rarr; Transformer 연산 &rarr; 벡터 출력

##### Dense Vector & Sparse Vector
Dense Vector  
모든 차원에 값이 채워져 있는 저차원 실수 벡터  
텍스트의 문맥적 의미를 벡터에 반영한다.  
사용처 : RAG의 의미 기반 문서 검색, 문장 유사도 비교, 텍스트 분류의 입력 특성  

Sparse Vector
해당 단어 위치에만 빈도 또는 가중치 값이 있고, 나머지는 0인 고차원 벡터  
정확한 키워드 매칭 기반 검색을 가능하게 하고, 특정 단어의 출현 여부를 명확히 구분할 수 있다.  
사용처 : BoW(Bag of Words), TF-IDF 기반의 키워드 검색, 하이브리드 검색의 키워드 매칭 구성 요소
