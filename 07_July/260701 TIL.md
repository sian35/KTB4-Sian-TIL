### 새로 배운 내용 : (LangGraph) Memory & Architecture
### Memory
- LLM은 기본적으로 무상태(Stateless)이다.
- LangGraph에서의 memory란 그래프 state에 누적해두는 정보이다.
#### Short-term memory
- 단기 기억
- 같은 스레드 안에서의 대화 이력과 실행 맥락을 유지할 수 있게 하는 세션 단위 메모리이다.
#### Long-term memmory
- 장기 기억
- 기억을 격상 시켜서 원본 그대로 또는 요약본을 저장한다.
- e.g.) RAG에서는 장기 기억이 검색의 대상인 것이다.
- **스레드가 바뀌어도** Store에 남아 있어서 같은 사용자 네임스페이스를 통해 여러 대화에서 재사용할 수 있는 장기 메모리이다.
#### Interrupt
- 실행 흐름을 일시 중단하고 State를 체크포인트에 저장한 뒤, 사람의 판단을 입력 받아 재개하는 메커니즘이다.
- 종료(terminate)가 아님
- 서버 프로세스가 대기 상태로 떠 있는 것이 아니라 실행이 멈추었다가 재개되는 것.

#### Human-in-the-Loop
- Interrupt와 Checkpointer를 사용하는 협업 설계 패턴
- 반자율주행차의 안전 운전자에 비유할 수 있다.
- 사람의 역할
	- 승인
	- 수정
	- 거부
	- 정보 제공

#### Streaming
- 그래프가 실행되는 동안 만들어지는 노드 결과, 토큰, State 변화를 완료 전부터 하나씩 받아 볼 수 있게 하는 실행 방식
- invoke()와의 차이점
	- invoke() : 그래프 실행이 끝난 뒤 최종 결화를 한번에 반환
	- stream() : 그래프 실행 중간에 발생하는 이벤트를 그때그때 전달
- Streaming을 통해 첫 토큰 도달 시간, 평균 토큰 생성 시간이 짧아진다.

### Architecture
#### Plan-and-Execute Pattern
- LLM이 사용자 요청을 받아 계획을 짜고, 그 계획을 순차적으로 실행하고, 필요에 따라 수정하는 에이전트 설계 패턴이다.
- 역할
	- Planner : 실행 가능한 단계 목록을 만든다.
	- Executor : 단계를 하나씩 실행하고 결과를 누적
	- Replanner : 결과를 보고 계획을 유지할지, 수정할지, 또는 최종 답변을 만들지 판단
#### Evaluator-Optimizer Pattern
- 생성된 결과를 평가 하고 기준에 미치지 못하면 다시 생성하는 설계 패턴이다.
- Generator가 결과를 만들고, Evaluator가 평가하여 generator가 다시 다듬는 루프를 반복하는 에이전트 설계 패턴
- 생성 -> 평가 -> 피드백 반영 -> 재생성
- 핵심은 역할 분리이다.

#### Subgraph
- 그래프를 노드로 등록해 사용하는 모듈화 단위이다.
- 즉, 상위 그래프 안에 들어가는 독립된 하위 그래프이다.
- 공유 키 : 상위 그래프와 서브 그래프가 주고받는 기준
- 비공유 키 : 서브 그래프 안에서만 사용하는 내부 필드
- 모듈 단위 테스트와 디버깅이 쉽다.
#### Multi-Agent System
- 여러 전문 Agent가 협업하도록 만든 랭그래프 시스템이다.
- 역할을 분리하여 도구 선택이 단순해지고 프롬프트가 짧고 명확해진다.
- 구성 요소
	- 전문 Agent : 특정 역할에 맞게 설계된 에이전트
	- Supervisor : 어느 agent가 일해야 하는지 결정하는 조율 노드
	- 공유 state : 여러 에이전트가 함께 읽고 쓰는 상위 그래프의 state
	- 종료 조건 : 더 이상 호출할 에이전트가 없을 때 그래프를 끝내는 기준
